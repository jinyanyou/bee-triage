# 벌집 신고 사전 분류 — 프로토타입

2026 AI·디지털 기반 사회문제 해결 챌린지 출품작 「디지털 기반 국가 사회현안 해결 서비스」의
**2. 프로토타입 개발** 산출물입니다.

위험도가 검증되지 않은 벌집 신고가 119로 집중되는 문제를 풀기 위해,
**신고 접수 이전 단계**에서 챗봇 문진 → 사진 위험도 판별 → 위험도 기반 자동 매칭을 수행합니다.

---

## 1. 실행

### Windows

```
prototype\run.bat
```

가상환경 생성 → 의존성 설치 → 서버 기동까지 한 번에 합니다.
브라우저에서 <http://127.0.0.1:8000> 을 엽니다.

### macOS / Linux

```
./run.sh
```

### API 키 (선택)

`.env.example`를 `.env`로 복사하고 `ANTHROPIC_API_KEY`를 채우면 **LIVE 모드**로 동작합니다.
키가 없으면 자동으로 **MOCK 모드**가 되며, 데모 시나리오 4종과 규칙 기반 슬롯 추출로
발표 시연이 그대로 가능합니다. 네트워크 사고로 시연이 멈추지 않게 하려는 설계입니다.

|  | LIVE 모드 | MOCK 모드 |
|---|---|---|
| 슬롯 추출 | Claude Tool Use (`claude-opus-5`) | 정규식·키워드 규칙 |
| 사진 판별 | Claude Vision + few-shot, Tool Use | 데모 시나리오 4종 |
| 임의 사진 업로드 | 실제 판별 | **판별불가 → 119** (안전장치 그대로 시연) |
| 스코어링·매칭·대시보드 | 동일 | 동일 |

## 2. 라이브 데모 배포 (Vercel)

이 저장소를 Vercel에 연결하면 **설정 없이 그대로 배포됩니다.**
Vercel이 `requirements.txt`에서 FastAPI를 감지하고 `app/main.py`의 `app`을 진입점으로 잡습니다.

```
Vercel → Add New Project → 이 저장소 선택 → Deploy
```

빌드 명령이나 환경변수를 따로 넣지 않아도 됩니다.

### 서버리스라서 달라지는 점 하나

Vercel 함수는 **파일시스템이 읽기 전용**이라 SQLite에 신고를 쌓을 수 없습니다.
그래서 배포 환경에서는 신고 보관을 **브라우저(localStorage)**가 맡습니다.

| | 로컬 실행 | Vercel 배포 |
|---|---|---|
| `BEE_STORE` | `sqlite` (기본) | `client` (`VERCEL` 환경변수로 자동 감지) |
| 신고 저장 | `var/reports.db` | 방문자 브라우저 |
| 대시보드에 보이는 것 | 서버에 쌓인 전체 | 그 방문자가 만든 신고 |

화면 코드는 `web/store-client.js`의 어댑터를 통해 양쪽을 똑같이 다루므로,
`/`, `/dashboard`, `/partner` 세 화면 모두 배포판에서도 그대로 동작합니다.
심사위원마다 자기 신고만 보이는 구조라 데모로는 오히려 깔끔합니다.

강제로 확인하려면 `BEE_STORE=client`로 로컬 실행하면 배포판과 동일하게 동작합니다.

### 공개 데모는 MOCK 모드입니다

`ANTHROPIC_API_KEY`를 Vercel 환경변수에 **넣지 않습니다.** 키가 없으면 자동으로
MOCK 모드가 되어 데모 시나리오 4종과 규칙 기반 문진으로 전 과정이 돌아갑니다.
키를 공개 배포에 넣으면 누구나 호출해 과금이 발생합니다.
실제 Claude 판별은 발표 때 로컬(`.env`에 키 설정)로 보여주는 것을 권합니다.

## 3. 세 개의 화면 (3면 플랫폼)

| 경로 | 화면 | 대응 페르소나 |
|---|---|---|
| `/` | 시민 신고 | ① 놀란 신고자 김서준 |
| `/dashboard` | 소방 관제 | ② 생활안전대 소방관 박정민 |
| `/partner` | 업체·양봉인 수락 | ③ 지역 양봉업자 이근처 |

`/dashboard`는 우회율(소방력 절감률)과 사후 확인 기반 판별 정확도를 집계하고,
`/partner`는 카카오 알림톡을 대신해 매칭 수락·처리 결과 등록을 담당합니다.

## 4. 화면 디자인 규칙

색 사용에 원칙이 하나 있습니다. **브랜드 색과 위험등급 색을 분리합니다.**

| 역할 | 색 | 쓰이는 곳 |
|---|---|---|
| 상호작용 | 남색 `#1d4e89` | 버튼, 링크, 활성 탭, 진행 막대 — "누를 수 있는 것" |
| 고위험 | 적색 `#a81f14` | 등급 배지, 119 연계 배너 |
| 중위험 | 주황 `#d97706` | 등급 배지, 민간 업체 연계 |
| 저위험 | 녹색 `#0f6b46` | 등급 배지, 양봉협회 연계 |
| 판별불가 | 회색 `#55606c` | 등급 배지 (심각도가 아니라 "모름"을 뜻함) |

브랜드 색을 위험도에 섞어 쓰면 화면은 통일돼 보여도 정작 등급이 눈에 안 들어옵니다.
위험등급 3색은 색각이상 시뮬레이션(protan·deutan·tritan) 분리도와 배경 대비 3:1을
검증 스크립트로 통과시킨 조합입니다. 그리고 **색만으로 의미를 전달하지 않도록**
등급 배지에는 항상 한글 라벨이 함께 들어갑니다.

본문 글꼴은 Pretendard를 CDN에서 불러오고, 오프라인이면 맑은 고딕으로 자동 대체됩니다.
다크 모드는 OS 설정을 따르며, `<html data-theme="dark">`로 강제할 수도 있습니다.

## 5. 파이프라인

```
[시민] — 개인정보 처리 동의
  │ ① 챗봇 1차 문진            app/triage.py
  │    location_type / nest_size_cm / discovered_days_ago
  │    aggression_observed / reporter_risk_self_assessment
  ▼
  │ ② 사진 위험도 판별          app/vision.py
  │    고위험 · 중위험 · 저위험 · 판별불가 + 신뢰도 + 근거
  │    (EXIF에 촬영 좌표가 있으면 신고 위치 자동 입력)
  ▼
  │ ③ 가중합 스코어링           app/scoring.py
  │    비전 0.60 + 문진 0.25 + 크기 0.15
  ▼
  │ ④ 채널 연계                 app/dispatch.py → app/store.py 저장
  ├── 119 상황실      ← 고위험 또는 판별불가   → /dashboard
  ├── 양봉협회 지회   ← 꿀벌 분봉              → /partner
  └── 소독·방역업체   ← 그 외 비긴급           → /partner
                                                  │
                        사후 확인(실제 벌 종) ←────┘
                                │
                                └→ 판별 정확도 지표 + 재학습 데이터 (기획서 5.2)
```

### 설계상 중요한 세 가지

**FSM은 파이썬이 소유한다.** 어떤 슬롯이 남았는지, 다음에 무엇을 물을지, 사진 없이
다음 단계로 넘어가도 되는지는 LLM이 정하지 않습니다. LLM은 "자연어 → 슬롯 값" 추출과
재질문 문장 생성만 합니다. 같은 슬롯을 3회 물어도 답이 안 나오면 **위험한 쪽으로**
기본값을 채우고 넘어갑니다(시연 중 무한 반복 방지).

**애매하면 무조건 119.** 판별 신뢰도가 0.70 미만이면 등급을 `판별불가`로 강등하고
점수와 무관하게 119로 보냅니다. AI는 "안전을 확신할 때만" 저위험으로 분류합니다.

**문진 결과는 비전 단계에 전달하지 않는다.** 비전 0.6 / 문진 0.25 가중합이 같은 정보를
두 번 세지 않도록 두 신호를 독립적으로 유지했습니다.

## 6. 호출 방식 — Function Calling (Tool Use)

기획서 3.1 그대로, 두 LLM 호출 모두 **Tool Use**로 구현했습니다.

| 모듈 | 도구 이름 | 역할 |
|---|---|---|
| `app/vision.py` | `record_bee_assessment` | 판정 결과(등급·신뢰도·근거·지름) 기록 |
| `app/triage.py` | `fill_report_slots` | 발화에서 읽어낸 슬롯 값 채우기 |

둘 다 `strict: true`라 스키마를 벗어난 값이 올 수 없습니다.
`tool_choice`로 도구 호출을 강제하므로 `BEE_MODEL`은 강제 tool use를 지원하는
모델이어야 합니다(기본값 `claude-opus-5`는 지원).

모델이 도구를 호출하지 않거나 API 호출이 실패하면 **판별불가 → 119**로 떨어집니다.
슬롯 추출은 실패 시 규칙 기반으로 자동 대체되어 문진이 끊기지 않습니다.

## 7. few-shot 구성

두 층으로 되어 있습니다.

1. **텍스트 예시 3건** — 시스템 프롬프트에 입력→출력 쌍으로 포함 (고위험/중위험/판별불가).
2. **이미지 예시 9장** — `reference/manifest.json`에 등록된 사진을 판정 대상 앞에
   in-context exemplar로 붙입니다.

| 등급 | 장수 | 구성 |
|---|---|---|
| 고위험 | 3 | 벽면 폐쇄형 종 모양 집 / 실내 천장 폐쇄형 집 / 나무 구멍 장수말벌 |
| 중위험 | 3 | 처마 소형 개방형 집 / 육각방 노출 개방형 집 / 뱀허물쌍살벌 집 |
| 저위험 | 2 | 건물 외벽 분봉 덩어리 / 나뭇가지 분봉 덩어리 |
| 판별불가 | 1 | 하늘 배경 원거리 촬영 |

전부 iNaturalist의 CC 라이선스 관측 사진이며, 출처·라이선스·저작자는 `CREDITS.md`에
정리했습니다. 도감식 접사가 아니라 **시민이 폰으로 찍은 것과 비슷한 화각**으로 골랐습니다.
요청당 추가 전송량은 약 700KB(장변 640px로 축소)입니다.

사진을 더 넣거나 교체하는 방법은 `reference/README.md` 참고.

## 8. 비전 모델을 자체 학습하지 않은 이유

초안에서는 YOLOv8 탐지 + EfficientNet 분류를 자체 학습할 계획이었습니다.
후보 데이터셋을 실제로 확인한 결과는 다음과 같습니다.

| 자료 | 내용 | 적합성 |
|---|---|---|
| Roboflow `bee-detection-h59jf` | 클래스 4개 (drone / bee / pollenbee / queen), mAP@50 45.6% | **말벌 클래스 없음.** 전부 꿀벌 카스트 |
| AI-Hub 「지능형 양봉 데이터」(71488) | 벌통 내부 생애단계 + 백묵병 12클래스, 27만 장 | **말벌 없음.** 양봉 관리용 |
| `Gratheon/models-bee-detector` | 벌통 입구 꿀벌 계수 | 종 판별 아님 |

세 자료 모두 **양봉가가 벌통 안/입구를 찍은 사진** 도메인입니다.
우리에게 필요한 것은 **겁먹은 시민이 수 미터 밖에서 폰으로 찍은 처마 밑 벌집**을
장수말벌·등검은말벌 vs 꿀벌로 나누는 일이라 도메인이 어긋납니다.

따라서 프로토타입은 멀티모달 LLM에 위험등급 기준과 few-shot 예시를 제시해 판별하고,
실제 신고 사진이 누적되는 파일럿 단계에서 자체 모델로 대체하는 경로를 택했습니다.

## 9. 정확도 평가

`eval/` 폴더에 평가 harness가 있습니다. 자세한 사용법은 `eval/README.md`.

```
.venv\Scripts\python.exe -m eval.run_eval
```

단순 정확도보다 **안전 지표**를 봅니다.

| 지표 | 의미 | 목표 |
|---|---|---|
| **위험 과소평가** | 실제보다 낮은 등급으로 판정 | **0건** |
| 불필요 119 이관 | 실제 저위험인데 119로 보냄 | 낮을수록 좋음 |
| 등급 일치율 | 정답과 판정이 같은 비율 | 참고 지표 |

리포트에 **신뢰도 임계값 스윕**(0.50~0.90)이 포함되어, 현재 기본값 `0.70`이
적절한지 근거를 만들 수 있습니다. 공모전 유의사항의 "주관기관은 필요 시 사용한
AI 도구 및 활용 방식에 대한 설명을 요구할 수 있음"에 대비한 장치입니다.

**표본 20장이 준비되어 있습니다** (`eval/images/` + `eval/labels.csv`).

| 등급 | 장수 | 내용 |
|---|---|---|
| 고위험 | 6 | 등검은말벌·좀말벌·꼬마장수말벌 폐쇄형 집, 대형 개체 |
| 중위험 | 5 | 쌍살벌·뱀허물쌍살벌 개방형 집 (3장은 국내 관측) |
| 저위험 | 6 | 양봉꿀벌·토종꿀벌 분봉 덩어리, 군집 |
| 판별불가 | 3 | 벌이 안 보이는 사진, 판독 불가 구도, 벌이 아닌 피사체(새) |

참조 사진과 평가 표본은 **서로 겹치지 않습니다.**
`ANTHROPIC_API_KEY`만 넣으면 바로 실행됩니다. **아직 실행하지 않았습니다** (키 없음).

## 11. 개인정보 처리 (본선 '실현성' 항목 대비)

- **사진은 저장하지 않습니다.** 메모리에서 판별에 쓰고 즉시 버립니다. DB에는 판별
  결과(등급·근거 텍스트)만 남습니다.
- 신고 시작 전 **동의 화면**에서 수집 항목과 보존기간을 고지합니다.
- 신고 좌표는 매칭에 필요한 만큼만 저장하고 **90일 경과 시 자동 파기**
  (`app/store.py`의 `RETENTION_DAYS`, 서버 기동 시 `purge_expired()` 실행).
- 양봉협회 지회장 개인 연락처는 저장하지 않고 협회 사무국 경유 구조로 구현했습니다.

## 14. 알려진 한계

- **LIVE 모드(Tool Use 경로)는 실제 API로 아직 검증하지 않았습니다.** API 키가 없어
  스키마 요건(strict / additionalProperties / required 일치)만 로컬에서 확인했습니다.
  키를 넣고 사진 한 장으로 먼저 확인해 주세요.
- 판별 정확도를 아직 측정하지 않았습니다 (7장 참고). 신뢰도 임계값 `0.70`은 현재
  근거 없이 정한 값입니다. 표본은 준비돼 있으니 키만 넣으면 측정됩니다.
- **기획서 위험등급 분류를 한 군데 수정했습니다.** 초안은 좀말벌을 중위험으로
  두었으나, 좀말벌(*Vespa analis*)·꼬마장수말벌(*Vespa simillima*)도 종이질 외피의
  폐쇄형 집을 짓고 집단 방어 공격을 합니다. 형태로는 장수말벌·등검은말벌과 구분이
  어려워 중위험으로 두면 안전하지 않습니다. 코드에서는 **말벌속(Vespa) 전반을 고위험**,
  중위험은 **쌍살벌류(Polistes·Parapolybia)**로 한정했습니다. 기획서 3.2의 등급표도
  같이 고쳐야 합니다.
- 참조·평가 사진은 국내 관측이 5장뿐이고 나머지는 동아시아·유럽 관측입니다.
  같은 종이라도 지역 개체는 색 패턴이 조금씩 다를 수 있습니다.
- `cc-by-nc` 사진이 20장 있습니다. 상업적 활용 단계에서는 교체가 필요합니다 (`CREDITS.md`).
- 매칭 DB 전화번호 결측 57.5%(586곳). 농어촌 지역은 반경 내 연락가능 업체가 없을 수
  있고, 데모 위치 「경북 울진군」이 그 사례입니다. 매칭 공백을 숨기지 않고 보여줍니다.
- 소독업 인허가가 곧 벌집 제거 서비스 제공을 뜻하지는 않습니다.
- EXIF 좌표는 카카오톡 등으로 전달된 사진에서는 대부분 제거되어 읽히지 않습니다.
- 문진 세션은 여전히 인메모리입니다(신고 확정 시점에 DB로 저장). 서버를 재시작하면
  진행 중이던 문진은 사라집니다.
